# Dice, keepsakes and items

All three are structs with effects that hook named events. Definitions are built once per run from `oRunManager/Create_0` (`generate_dice_bag`, `define_items`, `define_keepsakes`).

## Dice: scDice

- `make_die_struct(amount, value, action, possible_type, permanence, name, description, rarity, price, effects, distribution)`; fields also include `min_roll_bonus`, `rolled_value`, `forced_roll`, `roll_twice`, reset hooks, `statistics`, `uid`.
- Each die is a `global.die_*` template registered with `ds_list_add(global.master_dice_list, clone_die(global.die_x, ""))` right after it. Also `global.starter_dice_list`, `global.alignment_dice_list`.
- `clone_die(src, permanence)` deep-copies. **Copies keep the uid**; anything that makes a second live copy gives it `global._die_uid_counter++` (bag dice get fresh uids at every room start in `oRunManager/Other_4`).
- **Dice effects fire through `die_fire_effects`** (T03). Broadcast events (`after_roll_die`, `on_dice_played_to_slot`, `on_dice_ejected`, fired for every die in the queue by `dice_trigger_effects`) are owner-only by default: an effect fires only when the event is about its own die (`effect_subject_die` reads `_ejected_die`, `_d_struct`, `die`, `_slot_die` or `_die_struct`). Set `owner_only: false` on an effect to react to other dice. Single-die events (`on_roll_die`, `on_sacrifice_die`, `on_not_used`, `on_dice_dealt`) go through `trigger_die_effects_single`. Old manual uid checks still work. Dice in fights are drawn in code: `draw_die(x, y, r, sides, face, col, angle, alpha)` (shape by size from `die_shape_points`, pips from `die_pip_layout`, -1 face shows "d6"), `draw_die_shape` for silhouettes and outlines. A core's effect on a die: `draw_dice_distribution(die, x, y, centered, scale)`, bars from one baseline with the faces under it on a dark plate; `y` is the bottom of the whole graphic. Elsewhere dice still use the sDice / sDiceIcon sprites. After a die's effects run, `_data.die_effects_added` holds what they added to `_d_amount` (Chainmaster's Anchor uses it to tell if a Followthrough fired, and repeats only that part). Keepsakes, items and debuffs still have their own trigger shapes (rest of T03).
- Keywords (Coin, Sticky, Exclusive, Loose, Stowaway, Favourite, Multitype, Followthrough) are data: each die has a `keywords` array, set right after its definition (`global.die_x.keywords = ["Coin"];`). Check with `die_has_keyword(die, "Coin")`, add with `die_add_keyword(die, "Coin")` (also prefixes the description). Saved with each bag die. Icons (`draw_dice_keywords`) and a die's own tooltip keyword boxes read the list too; `string_has_keyword` is only for searching other text (keepsake and item descriptions).
- Show a die's text with `die_description(die)`, never `die.description` directly: descriptions can hold `{min}`, `{max}`, `{min2}`, `{max2}`, `{half}`, filled in from the die's current value and min_roll_bonus, so upgrades change the text too.
- After changing a die's size call `die_size_changed(die)`: the Coin keyword follows size (a die is a coin exactly when it is a d2). Every size change does this: Hammer, Cutters, Roundshot and the other +2 events, Artisan's Ember (and its end-of-fight reset). `min_roll_bonus` and `distribution` changes need nothing extra.
- `deal_single_die` draws from `global.dice_bag` (reshuffles the discard pile; the F1 menu can inject a die via `debug_take_next_die`). `oDice` is the in-hand instance (`struct` holds the die).
- `get_dice_output(die, slot, index, read_only, owner)`: with no slot (-1 or undefined) the die is previewed as its own `action_type`. Hover and bag previews must pass `read_only` true. An unslotted die always has `slot_num` -1 in the context; effects that count slots (Surge, Kill Coin) must check `slot_num >= 0` first. `oDice` copies `action_type`, `dice_amount`, `dice_value`, `possible_type` from its `struct` every step; the struct is the truth.
- Permanence strings: `"base"` (stays a turn), `"temporary"`, `"temporary none"`, `"sticky"`.
- Keyword icons are drawn in code: `draw_keyword_icon(key, x, y, scale, alpha)` (scHelpers; a parchment roundel ringed in the keyword's colour with an ink glyph). `draw_dice_keywords(die, x, y, scale, alpha, where)` (centred on the die's bottom edge, `die_bottom_edge(sides, r)`, so they overlap it by half) shows only the keywords whose `icon_on` (global.keywords, oRunManager Create) includes `where`: "hand" (dice in hand in a fight: Stowaway, Followthrough, Exclusive, Sticky, Loose) or "slot" (Sticky, Loose). Nowhere else (shop, rewards, cards): the words do it. Keyword tooltip boxes draw the same icon (`keyword_from_index`); Might and Balance keep their sprite.
- Colour: `get_dice_color(die.possible_type)` (not `action_type`): one colour, a multitype die's first type (no more pulsing blend), for text and particles. To draw a die use `die_colours(possible_type)` (an array): `draw_die` / `draw_die_shape` take a colour or that array and split a multitype die diagonally (`draw_split_polygon`; `colours_merge` shades an array). Card headers use `draw_header_band` (scHelpers), split the same way. Every die is drawn in code now (oDice in every room, `dice_particle_draw` for oDiceParticle, shop shelf, fight and bounty rewards, the debug dice list): sDice is only a fallback for an oDice without a struct. Unrolled dice show their size ("d6"); keyword icons sit small above them.

## Keepsakes: scKeepsakes

- Struct `{ _id, name, desc, sub_image, state, trigger: function(event, data) }`, optional `price`, `replaces` (id it swaps out in place, e.g. Deep Lens → Looking Glass).
- Lists: `global.master_keepsake_list` (all), `rollable_keepsake_list` (rewards/elites/treasure), `shop_keepsake_list`, `boss_keepsake_list`. Owned: `oRunManager.keepsakes` (ds_list, order = bar order).
- `gain_keepsake(ks, list_to_remove_from)` then fires `on_keepsake_acquired`. `get_keepsake_by_id` returns the master struct (shared).
- `runmanager_trigger_keepsakes(event, data)` calls every owned keepsake's `trigger`; each filters by event. `trigger_keepsake_visual()` pops its icon.
- Sprite: `sKeepsake`, frame `sub_image`.

## Items (consumables and cores): scItems

- Struct `{ sprite, index, name, description, type: "consumable"|"core", distribution, rarity, price, effects: { trigger, flags(), modify(ctx) } }`.
- Triggers: `on_clicked` (used from the item bar, `oRunManager/Draw_64`) or `on_item_played_to_slot` (dragged onto a slot, `oCombat/Draw_64`). `flags()` says whether it can be used right now.
- Owned: `oRunManager.items` array (length = `max_items`, `undefined` = empty slot). `gain_item`, `get_first_free_item_slot`, `get_item_by_name`.
- Cores change a die's `distribution` at the workbench (Drill). The alignment pair ("compass", "lodestone", in Odd and Even's item slots and art) is shaped live by `core_alignment_lean()` (-1 ruthless to +1 merciful) inside `define_dice_distributions`; old "odd"/"even" dice still roll, and `get_item_by_name` maps the old core names. Any die made outside `deal_single_die` in a fight must call `die_roll_faces` itself (Message in a Bottle forgot, B132).

## Event names (ctx fields vary)

Turn: `on_combat_started`, `on_turn_start` (bonus_dice, intel, turn_count), `on_player_turn_end`, `on_enemy_turn_start`, `on_enemy_turn_end`, `on_round_end`, `on_combat_end`.
Dice: `on_dice_dealt`, `on_dice_played_to_slot`, `on_roll_die` (min_roll, max_roll, _d_amount, read_only...), `after_roll_die`, `after_slot_damage_calculated`, `on_not_used`, `on_dice_ejected`, `on_sacrifice_die`, `on_new_slot_created`, `after_new_slot_created`, `after_change_current_action`, `on_bag_empty`.
Other: `on_enemy_death`, `on_player_block_gained`, `on_player_debuffed`, `on_debuff_acquired`, `on_consumable_used`, `on_keepsake_acquired`, `on_rest`. Buff-only: `before_enemy_take_damage`, `on_enemy_take_damage`.

`on_roll_die` runs during previews too (`read_only` true): effects must not change state unless `!read_only`. As a die is dealt it runs with `on_deal` true (`die_roll_faces`): roll-shaping goes there (Starver's Efficiency, Nav Chart use it).

**The three moments (rolled dice, `docs/design-port-dice-keepsakes.md`):** when rolled = `on_die_rolled` (fired by `die_roll_faces` after the faces are rolled, on deal and ink reroll; context `{ _die_struct, face, min_roll, max_roll }`; a forced face lands here too) for "if it rolls X: draw / buff" (Squall, Offhand, Balanced, Warrior, Rusty Rudder, Nav Chart); in the queue = `on_roll_die` bonuses, live in slot totals; when it acts = `after_roll_die` for outcomes (block, heal, damage). Repeater Rail adds its bonus in `on_roll_die` from the die's place in its slot (`die_index`), so every `get_dice_output` call for a die in a slot passes its index (scoring and the slot total). Topographic Map caps its "valley" draws at 2 a turn (`state.turn`, `state.draws`). `on_die_inked` fires when a die is rerolled or redrawn with ink (`redrawn` true/false; Deepdiver). `die_effect_popup(die, text, col)` shows a word over the die in hand. A "draw a die" effect adds to `oCombat.dice_to_deal` (queued), never calls `deal_single_die` from inside a deal. Loose is retired (no keyword entry).
