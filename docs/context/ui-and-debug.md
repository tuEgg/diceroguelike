# UI helpers, display and the debug menu

## Drawing and input helpers: scHelpers

- `mouse_hovering(x, y, w, h, centred, hover_sound, click_sound, conditions, layer, id)`: returns false if `global.ui_layer` is above `layer` or input is disabled. Use it for anything clickable.
- `global.ui_layer` (enum `UI_LAYER` in `oMainMenu/Create_0`): `BASE, POPUP, BAG, SETTINGS, DEBUG`. Higher layers block lower ones. Exception: while the bag is open (`UI_LAYER.BAG`) the top bar can still be hovered for tooltips (`global.ui_peek_top_bar`, set around the top bar in oRunManager Draw GUI); its clicks check for the base layer.
- Tooltips: `queue_tooltip(x, y, name, desc, icon, index, die)` queues one per frame; `draw_all_tooltips()` draws it (called at the end of `oRunManager` Draw GUI End, `Draw_75`, so tooltips sit above every window) with keyword sub-tooltips found in the description. Titles stay on one line. Draw GUI End order: dice list, `tips_draw`, `insight_panel_draw`, `dragged_item_draw` (carried core/potion), `pause_draw`, `run_summary_draw`, then tooltips.
- Tooltip stack: `draw_all_tooltips` measures the main box and each keyword box (`draw_tooltip_box(..., measure_only)`), keeps the whole stack on screen, then draws keywords as compact boxes right under the main one. `buff_tooltip_text(inst)` (scDebuffs) builds buff/debuff tooltips.
- Accessibility: Settings > Display > Action icons on dice (`global.action_icons`) draws `draw_action_type_icon` on dice in hand (oDice Draw GUI) and in slots (oCombat Draw GUI).
- Cursor: `cursor_draw()` (last thing in oRunManager Draw GUI End during a run; oSettingsMenu Draw GUI End on the main menu) draws the game's pointer and hides the system one while `global.custom_cursor` is on (Settings > Display, settings.json). `mouse_hovering` stamps `global.cursor_hover_time` when it hits, which lights the cursor.
- Button colours by role (oSettingsMenu Create): `global.ui_primary` (the main go action), `ui_neutral` (ordinary choices, leaving), `ui_danger` (costly), `ui_quiet` (skippable). Red/blue/green/yellow are kept for attack/block/heal/insight. Rooms that mark a ready Exit with c_red draw it through `ui_button_col`. Dimming overlays start below `ui_top_bar_h()` so the top bar stays lit.
- Text: `draw_outline_text(str, outline, fill, width, x, y, scale, alpha, angle, max_width)`; `[tag]` colour markup via `colorcode_text`. Fonts `ftDefault`, `ftDescriptions`, `ftSmall`, `ftTiny`, `ftBig`, `ftBigger`, `ftDamage`.
- Buttons: `draw_gui_button(..., _disabled_reason)` returns `{ hover, click, ... }`; it draws a shadow, sinks while held, mutes a disabled button and shows `_disabled_reason` on hover. Windows use `ui_panel(x1, y1, x2, y2, alpha)` and `ui_divider` (logbook style, like the tooltips). Tooltips asked for at the mouse sit beside the rectangle `mouse_hovering` last matched this frame (`global.hover_rect`): right of it, top-aligned, flipped left near the screen edge. `ui_button(cx, cy, w, h, scale_ref, text, col, active, reason, layer, alpha, font)` is the kit's centred button (big text that scales, optional fade). Settings, the bag view, pause, the voyage summary and the At sea and spread-end choices use `ui_panel`; the rewards screen only a `ui_divider`. The dice picker raises `UI_LAYER.BAG` while open. `draw_wonky_rectangle` draws hand-drawn panels straight to the screen with triangles (no surfaces; the old cached 8x surfaces churned on hover and drew black on web), its wobble seeded from position and colour so it holds still while a button grows. `draw_mouse_hint(x, y, "left"|"right", text)` draws a small mouse with one button lit.
- `throw_error(title, desc)` shows a red tooltip for ~1.5s.
- Bag view and the dice picker (`dice_selection`) are drawn in `oRunManager/Draw_75` (Draw GUI End), above every room's windows; the bag icon itself stays in Draw_64. Bag view and the debug dice list (`oRunManager/Draw_75`): each die box is edged in its rarity colour; scrollbars drag while `scroll_dragging` is true, which clears whenever the mouse button is up. Use GUI-space mouse positions (`device_mouse_y_to_gui`), never `mouse_y`, for anything drawn in Draw GUI.

## Display: scDisplay, scSettings

`apply_resolution()` (every room start) sets the window and application surface to `global.resolution_options[global.resolution_index]` (1080p, 1440p) but keeps the GUI and camera at 1920x1080, so the fixed 1080p layout works at any 16:9 size (B83); `global.ui_scale` is therefore 1. `global.gui` holds proportional sizes (`update_gui_layout`). oSettingsMenu Create turns on the best multisample anti-aliasing (`display_reset`, desktop) and 64-segment circles, so shapes drawn in code have smooth edges. Web builds (`IS_BROWSER`): `apply_resolution` hands over to `apply_browser_resolution` (always 1920x1080 inside, canvas fitted 16:9 into the page, refit by `browser_check_resize` from oSettingsMenu Step); no Resolution setting, no Exit button or double-Escape quit, fullscreen not restored at start-up. Export and smoke test: `docs/web-build.md`.

## Debug menu: scDebug, `oDebugger` (persistent, depth -10000)

- `DEBUG_TOOLS` macro: true when run from the IDE (`debug_mode || GM_build_type == "run"`). Everything below is off in exported builds.
- **F1** opens the panel (`global.dbg` holds its state); Escape closes it. Tabs: Run, Fight, Combat, Dice, Keepsakes, Items, Events, Rooms, Hotkeys. Widgets are immediate mode: `debug_button` returns true on click, `debug_label`, `debug_hovered` + `debug_tip` for hover tooltips (drawn by the menu itself, on top).
- **Hotkeys** (`debug_hotkeys`, menu closed): Space kill all and end turn, Backspace take 20, H heal, D draw, N complete spread, F2/F3/F4 speed x1/x2/x4. Older letter keys in `oRunManager/Step_0` (R, C, L, A, S, E, B, T, W, X, G, Q) also use `DEBUG_TOOLS`.
- **Hooks the game calls** (each does nothing unless the menu asked): `debug_apply_pending_fight` (oCombat Create), `debug_take_next_die` (deal_single_die), `debug_take_forced_event_index` (generate_event), `debug_turn_intel` (turn start), `debug_skip_intro` (oCutsceneManager Create: true only in a debug run, F6).
- The intro never plays in a debug run (F6); otherwise it plays once (progress.json `intro_seen`) and Settings > Gameplay > Intro next run replays it. (`debug_settings.json` still holds an unused `skip_intro`.)
- Leaving a fight via the menu restores the bag from `bag_snapshot`.
- The enemy and event name lists at the top of `debug_menu_init` are typed by hand: add new enemies and events there too.
